### B. KPI 띠 (4카드)

4개 카드 균등 배치, 각 카드 구성:

```
┌────────────────────┐
│ 전체 매출          │  ← 라벨
│ ₩12,583,120        │  ← 값 (24pt bold)
│ ↑ 8.2% (vs 전주)   │  ← delta (녹/적/회 색상)
└────────────────────┘
```

| 카드 | 값 계산 | delta 방향성 |
|---|---|---|
| 매출 | 쿠팡 보고서 sum(매출) | ↑ 개선 (녹) |
| 광고매출 | sum(광고매출) + 비율 "(52%)" | ↑ 개선 (녹) |
| 광고 순이익 ⓘ | 광고매출 − 광고비 − (광고매출 × (원가율 + 수수료율)). 원가 미입력 시 "원가 입력 필요" 표시 + CTA | ↑ 개선 (녹) |
| 예산 소진률 | sum(당일 광고비) / sum(일예산). % 게이지 바 추가 | 70~95% 정상, >95% 경고, <60% 황 |

> "광고 순이익" 라벨 옆 ⓘ 툴팁: "부가세·쿠폰·프로모션·배송비·반품은 미반영. 실제 정산액과 차이가 날 수 있습니다."

**원가 미입력 처리**: 순이익 카드 값 영역을 `원가 미입력 (12개 상품)` + 우측 `[원가 입력 →]` 버튼. 버튼 클릭 → `/settings/cogs` 이동.

### C. ADMIZER 인사이트 영역

상단 헤더 좌측 "ADMIZER 인사이트", 우측 "더보기 ({{matched_count}}) →" 링크 → 화면 04 인사이트. 카운트는 **실제 매칭된 케이스 수**로 동적 렌더 (하드코딩 금지).

**카드 구성 (최대 5개, 중요도 순 정렬)**:

```
┌──────────────────────────────────────┐
│ 🟡 [매출최적화]                       │  ← 심각도 색상 + 분류 배지
│ 3개 캠페인에서 CPC가 급등했습니다.    │  ← LLM 생성 1문장
│                                      │
│ ▸ 탄소매트 · 보조배터리 · 효도라디오 │  ← 대상 캠페인 (전문가 모드만)
│                                      │
│ [자동 추천 받기]  [상세 분석 →]      │  ← CTA 2개
└──────────────────────────────────────┘
```

> 심각도 색상은 룰 YAML의 `severity` 필드를 그대로 사용한다. 예에서 CPC 급등(`CPC_SPIKE`)은 `warning`=🟡로 매칭. 🔴/🟡/🟢는 각각 `critical`/`warning`/`info`.

| 요소 | 간단모드 | 전문가모드 |
|---|---|---|
| 심각도 | 🔴 긴급 / 🟡 주의 / 🟢 정보 | 동일 |
| 분류 배지 | 없음 | [매출최적화] / [수동광고] / [아이템위너] 등 |
| 대상 캠페인 | 숨김 | 최대 3개 표시 |
| 근거 지표 | 숨김 | "CPC 1,200원 → 1,850원 (+54%)" 표시 |
| 주 CTA | [자동 추천 받기] 1개 | [자동 추천 받기] + [상세 분석 →] 2개 |

**CTA 동작**:
- **자동 추천 받기**: 인라인 확장 → 룰 엔진이 매칭한 케이스 기반 액션 2~3개 제시. 각 액션 옆 `[적용]` 버튼. 적용 클릭 시 **변경 미리보기 모달** 호출(공통 패턴).
- **상세 분석 →**: 화면 02 캠페인 리스트 진단 패널로 이동 + 해당 캠페인 auto-select.

**기본 5개 카드 예시** (심각도는 룰 YAML 기준):
1. 🟡 매출최적화 3개 CPC 급등 (CPC_SPIKE, warning)
2. 🟡 최근 7일 키워드 10개가 기준 규칙 위배 (사용자 정의 규칙)
3. 🔴 매출최적화 키워드 1개 CPA 기준치 150% 초과 (HIGH_CVR_HIGH_CPA가 critical로 승격 — priority_modifier `budget_impact`)
4. 🔴 수동광고 1개 캠페인 매출 급감 (CVR_DROP + SALES_SURGE 대비)
5. 🟢 최근 7일 2개 캠페인 매출 +60% — 예산 상향 검토 (SALES_SURGE, info)

카드가 0개일 때: "모든 지표가 정상입니다 🎉 내일 다시 확인해 주세요." 일러스트.

### D. 캠페인 순위 그리드 (2×3)

6개 카드, 각각 상위 3개 항목 + "외 N개" 더보기 링크.

| 카드 | 소스 쿼리 (의사코드) | 클릭 이동 |
|---|---|---|
| 검색영역 ROAS 탑3 | `캠페인 ORDER BY 검색영역ROAS DESC LIMIT 3` | 화면 02, 필터=검색영역 |
| 비검색 ROAS 탑3 | `… 비검색영역ROAS DESC` | 화면 02, 필터=비검색 |
| 예산 부족 | `일예산 소진률 >= 95%` | 화면 02, 필터=예산임박 |
| 아이템위너 OFF | `아이템위너 이탈 AND 광고상태=OFF` | 화면 02, 필터=아이템위너 |
| 재고 없음 OFF | `재고=0 AND 광고상태=OFF` | 쿠팡 WING 재고 페이지(외부 링크) |
| 광고수익율 관리 | ROAS < `dashboard.low_roas_threshold` (기본 250%, 화면 05 표시 설정에서 조정) | 화면 02, 필터=저ROAS |

**카드 예시**:
```
┌──────────────────────────────┐
│ 검색영역 ROAS 순위            │
│                              │
│ 1. 마사지건 자동    600%     │
│ 2. 보조배터리 자동  430%     │
│ 3. 한일 탄소매트    320%     │
│                              │
│ 외 5개             상세보기 →│
└──────────────────────────────┘
```

간단모드에서는 상위 2개만(레이아웃 2행), 전문가모드에서는 3개 + "외 N개"(레이아웃 3행) 표시. 위 ASCII는 전문가모드 기준.

## 데이터 흐름

```
브라우저
  ├─ GET /api/dashboard/summary?period=7d&compare=prev_week
  │   → { kpi: {...}, insights: [...], rankings: {...}, lastSyncAt }
  ├─ POST /api/dashboard/refresh  (새로고침 버튼)
  │   → 쿠팡 보고서 API 강제 재동기화 후 summary 재반환
  └─ POST /api/insights/{id}/apply  (인사이트 카드 액션 적용)
      → 변경 전/후 프리뷰 반환 → 재확인 후 commit
```

**캐싱**: summary는 5분 캐시. `refresh` 호출 시만 무효화. 쿠팡 광고 보고서는 자체 동기화 스케줄러가 1시간마다 갱신.

**인사이트 생성 파이프라인**:
1. 최근 7/14/30일 집계 → 룰 엔진 21개 케이스 매칭 → 매칭 건을 심각도·임팩트 순 정렬 → 상위 5개 선택
2. 각 케이스 코드 + 실측 수치 → LLM 호출(캐시 30분) → 1문장 + 3액션 반환
3. 프런트엔드에 카드 형태로 렌더
