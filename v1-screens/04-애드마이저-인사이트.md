### 생성 파이프라인

```
1. 집계기
   - 최근 7/14/30일 지표 × 캠페인 × 영역(검색/비검색) 집계
2. 룰 엔진
   - 21개 케이스 YAML 매칭
   - 각 케이스는 조건(예: CVR > 5% AND ROAS < 300%)과 임팩트 점수 포함
3. 우선순위
   - 임팩트 점수 × 광고비 영향 → 정렬
   - 상위 10개까지 선택
4. LLM 생성 (룰베이스+LLM)
   - 케이스 코드 + 실측 수치를 프롬프트 템플릿에 주입
   - 4섹션(현상/인사이트/액션/결과) 포맷 강제
   - 결과 캐시 30분
```

### 간단 vs 전문가

| 요소 | 간단모드 | 전문가모드 |
|---|---|---|
| 카드 표시 개수 | 3 | 10 |
| 데이터 인사이트 | 1개만 | 3개 전체 |
| 예상 결과 표기 | 문장 | 수치 범위 |
| 액션 플랜 | 첫 2개 + "더 보기" | 전체 |
| 원문 링크 | 숨김 | 표시 |

### 액션 [적용] 동작

- 각 액션은 화면 02 (캠페인 분석·관리) 또는 화면 03 (규칙)의 실제 API를 호출
- 공통 **변경 미리보기 모달** 경유
- 적용 완료 후 카드에 "✅ ①단계 적용됨" 배지 추가
- 모든 단계 완료 시 카드 전체 회색 처리 + "모두 적용됨" 표시

### 데이터 흐름

```
GET  /api/insights/today?period=7d
     → { reports: [ { caseCode, severity, target, body, actions: [...] } ] }
POST /api/insights/:reportId/actions/:actionIdx/apply
     → 변경 미리보기 + commit 2단계
POST /api/insights/regenerate    (캐시 무효화 후 재생성)
```

### 수락 기준

- [ ] 초기 로딩 시 10개 카드가 순차 페이드인 (각 200ms 간격)
- [ ] LLM 생성 실패 시 해당 카드는 "룰 기반 기본 메시지"로 fallback
- [ ] 적용된 액션은 새로고침 후에도 "적용됨" 상태 유지 (서버 저장)
- [ ] 최신 30분 내 동일 케이스는 재생성 없이 캐시 반환
